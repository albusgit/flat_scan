What convert.py does (details in its docstring)
  1. fp32 copy of the ONNX graph (each fp16 weight's Cast folded: exact).
  2. onnx2tf -> fp32 .tflite, NHWC I/O (onnxsim folds BatchNorm into the convs in fp32, as ORT does).
  3. Own rewrite of the flatbuffer instead of the converter's float16 mode:
     - the converter's float16 mode rounds every fp32 constant (BatchNorm-folded weights, the fp32 biases) and
       writes `reduced_precision_support: fp16accfp32`. Measured on 3 photos (doctr__25, scanner_samples__tax,
       docres__190_in) against ORT: uvdoc rc0 p99 0.067-0.075 px, SD-HR p99 0.11-1.77 px with max 2.08 px on
       scanner_samples__tax (outside the 1 px tolerance), ShadeNet p99 0.008-0.063 levels. Not used;
     - fp16 storage only of constants whose values are fp16 numbers (exact);
     - SD-HR's 44 BatchNorm-folded filters unfolded: the ONNX fp16 weight, bias / s, then a per-channel MUL by
       the BatchNorm scale s carrying the conv's activation;
     - GPU forms: the PRelu slope (one value for 32 channels, [1,1,1]) per channel [1,1,32] in uvdoc and SD-HR;
       ShadeNet's x[1,1,1,96] * ones[1,16,11,1] broadcast (prepare_models.py's form of its Expand) as a
       RESIZE_NEAREST_NEIGHBOR of x to 16 x 11. Both exact (same values / same copies).
  Ops: uvdoc DEQUANTIZE 89, PAD 3, CONV_2D 45, ADD 13, CONCATENATION 1, MIRROR_PAD 2, PRELU 1
       SD-HR DEQUANTIZE 47, MUL 45, SUB 1, PAD 4, CONV_2D 45, ADD 13, CONCATENATION 1, MIRROR_PAD 2, PRELU 1,
             TANH 1, RESIZE_BILINEAR 1
       ShadeNet DEQUANTIZE 43, PAD 5, CONV_2D 25, MEAN 1, RESIZE_NEAREST_NEIGHBOR 1, CONCATENATION 6,
             RESIZE_BILINEAR 6, ADD 1, LOGISTIC 1

GPU compatibility
  tf.lite.experimental.Analyzer.analyze(model_path, gpu_compatibility=True) on each file:
    "Your model looks compatible with GPU delegate on TFLite runtime version 2.19.1." (all three)
  BUT this verdict carries no information in the builds available here: a negative control (a model with
  WHERE, GATHER_ND, GREATER, int32 MUL / ADD, TOPK_V2 and a Flex op) gets the same "looks compatible" from
  tensorflow 2.19.1 (Windows), ai-edge-litert 2.1.2 (Windows) and ai-edge-litert 1.4.0 (Linux, in WSL); none
  of their binaries contains the GPU checker's warning strings. So convert.py checks the graph itself
  (gpu_ops: every op in a form the GPU delegate's op parsers take: fp16-constant DEQUANTIZE, constant conv
  weights, H/W-only constant PAD, REFLECT MIRROR_PAD, ADD/SUB/MUL with a same-shape runtime operand or a
  scalar / per-channel constant, channel CONCATENATION, per-channel PRelu slope, constant-size resizes without
  align_corners, MEAN over H,W, TANH, LOGISTIC; all tensors float32 [1,H,W,C]). Result: no problem in any of
  the three files. The same check flags the two forms the rewrite fixed in onnx2tf's own output
  (PRELU slope [1,1,1] for 32 channels; MUL [1,1,1,96] x const [1,16,11,1] -> [1,16,11,96]) and every op of
  the negative control. This is a static check of my reading of the delegate's rules, not the delegate: the
  delegate's own verdict (partition log "Replacing N out of N node(s) ... yielding 1 partitions") needs a
  device with OpenCL (HUMAN GATE below).

Open issues for the runtime / app streams (found here, not fixed here: outside tools/litert)
  - LiteRT 1.4.0's GPU delegate crashes the process (SIGSEGV in TfLiteInterpreterCreate) where no OpenCL
    library loads, even with GL_ONLY (emulator above). infer.cpp should only create the delegate after its
    own dlopen of libOpenCL.so (or libOpenCL-pixel.so / libOpenCL-car.so, the names the delegate tries)
    succeeds, and treat the GPU backend as unavailable otherwise (the emulator then has no GPU backend).
  - Android 12+ (targetSdk >= 31): an app reaches the vendor's libOpenCL.so only if the manifest declares
    <uses-native-library android:name="libOpenCL.so" android:required="false"/> (and libOpenCL-pixel.so,
    libOpenCL-car.so likewise). Without it the delegate cannot load OpenCL inside the app, which with the
    crash above would take the app down. (gpu_check runs from adb shell, outside an app namespace.)
  - The GPU delegate options for full precision: is_precision_loss_allowed 0, inference_priority1
    MAX_PRECISION (1), priority2/3 AUTO; TfLiteGpuDelegateOptionsV2Default sets experimental_flags 1
    (ENABLE_QUANT) and max_delegated_partitions 1 (gpu_check.c prints them).
