    libtensorflowlite_gpu_jni.so exports TfLiteGpuDelegateOptionsV2Default, TfLiteGpuDelegateV2Create,

  no dependency between the two). TfLiteGpuDelegateOptionsV2 is 56 bytes in the header and in the library
  (TfLiteGpuDelegateOptionsV2Default writes 56 bytes; GPU delegate built as a classic TfLiteDelegate with Prepare,
  flags 4 = kTfLiteDelegateFlagsPerOperatorProfiling; not AllowDynamicTensors).
- Headers vendored (unchanged, Apache-2.0): core/third_party/litert/ (README.md has the AAR paths and hashes).

What was built (owned files: core/src/infer.{h,cpp}, core/src/nets.cpp backend_name / parse_backends,
core/third_party/litert/**, tools/litert_check/**; plus one include line in core/CMakeLists.txt, see deviations)
- infer.h: Backend::LiteRtGpu last in the enum; InferConfig::litert_dir after qnn_dir (contract C1).
  nets.cpp: backend_name(LiteRtGpu) = "gpu"; parse_backends takes "gpu" and "litert".
- infer.cpp (compiled in on Android / Linux when the vendored headers are on the include path, via __has_include;
  Windows and builds without them: "LiteRtGpu is not compiled into this build", the net moves on):
  * libtensorflowlite_jni.so then libtensorflowlite_gpu_jni.so dlopen'ed from litert_dir (RTLD_NOW|RTLD_LOCAL),
    every function resolved once per folder with dlsym (types from the vendored headers), never unloaded; a folder
    that fails is tried again later. No link-time dependency.
  * models through cfg.load: uvdoc_static.tflite, syntheticdoc_hr_static.tflite, shadenet_<H>x<W>.tflite (512x352 is
    the one shipped); no .onnx fallback; the page finder never on this backend. One interpreter per net and input
    shape. Input float32 NHWC [N,H,W,C] checked against run()'s NCHW shape; NCHW -> NHWC in, every 4-D output
    NHWC -> NCHW out (shape [N,C,H,W]); other outputs copied as they are; all float32 or no session.
  * GPU delegate options: is_precision_loss_allowed 0, inference_priority1/2/3 MAX_PRECISION / MIN_LATENCY /
    MIN_MEMORY_USAGE (fp32 compute), inference_preference SUSTAINED_SPEED, max_delegated_partitions 1; with a
    cache_dir, ENABLE_SERIALIZATION into cache_dir with model_token fs_<model sha256[:16]>_<sha256(SoC|build
    fingerprint|LiteRT version|fp32)[:8]> (the OpenCL backend serialises; a delegation that fails with the cache is
    retried once without it).
  * whole graph or nothing: the interpreter is made without delegates, then TfLiteInterpreterModifyGraphWithDelegate
    gets a copy of the GPU delegate whose Prepare wraps the delegate's own and then reads the execution plan
    (TfLiteContext::GetExecutionPlan / GetNodeAndRegistration; the opaque API for an opaque-built delegate): exactly
    one node, a kTfLiteBuiltinDelegate kernel, else it returns an error, the interpreter restores its plan and the
    net moves to the next backend ("the GPU delegate takes only part of the graph (N nodes -> K, some on the CPU)").
  * one LiteRT thread per Inference: every interpreter is created, run and deleted there (the delegate's OpenGL ES
    backend binds its EGL context to the thread that applied it); nets on the GPU run one at a time. The per-NetId
    lock of run() is unchanged.
  * failures as the other backends: any failure (libraries, model, delegate, partial graph, Invoke) -> the net drops
    to the next backend, CPU last; the interpreter's error reports are collected into the logged reason.
    last_ms: input conversion + Invoke + output conversion, measured on the LiteRT thread (queue wait excluded).
  * OpenCL guard: LiteRT 1.4.0's GPU delegate runs its OpenCL lookup in every Prepare (also with GL_ONLY):
    libOpenCL.so, libOpenCL-pixel.so, libOpenCL-car.so by dlopen, else libvndksupport's android_load_sphal_library;
    when all fail it appends dlerror() to a std::string, but the sphal function has consumed dlerror() (it logs it),
    so strlen(NULL) segfaults (disassembly of libtensorflowlite_gpu_jni.so x86_64 at 0x1f58a2..0x1f58cd, the strings
    "Failed to load OpenCL library with dlopen: " / ". Trying ICD loader."; reproduced on the emulator with the
    delegate alone, scratch lrt_probe.cpp, before any of this code). infer.cpp repeats that lookup first
    (opencl_found); no OpenCL library -> no delegate, the net stays on the next backend. So an OpenGL-ES-only phone
    gets no LiteRT GPU (no crash); see open issues.
- CPU / ORT paths: the ORT code is textually unchanged (a LiteRT branch before it in make_session and run(); the
  session key changes only for LiteRtGpu).

HUMAN GATE: the first GPU run, on the Galaxy S24 FE (Exynos 2400e, Xclipse 940) or any Mali / Adreno phone
1. Build: tools/litert_check/README.md for ABI arm64-v8a (ORT: onnxruntime-android-1.22.0.aar unpacked).
2. adb shell mkdir -p /data/local/tmp/lrt/lib /data/local/tmp/lrt/models /data/local/tmp/lrt/cache, then push
   build/arm64-v8a/litert_check and ORT jni/arm64-v8a/libonnxruntime.so to /data/local/tmp/lrt/;
   C:/Users/User/Android/litert/litert-1.4.0/x/jni/arm64-v8a/libtensorflowlite_jni.so and
   litert-gpu-1.4.0/x/jni/arm64-v8a/libtensorflowlite_gpu_jni.so to lib/; the three .tflite of
   app/src/main/litert/models/ and uvdoc.onnx, syntheticdoc_hr.onnx, shadenet.onnx of app/src/main/assets/models/
   to models/. adb shell chmod 755 /data/local/tmp/lrt/litert_check
3. adb shell ls /vendor/lib64/libOpenCL.so /system/vendor/lib64/libOpenCL.so   (OpenCL present? record it)
4. For NET in uvdoc synthdoc_hr shadenet:
     adb logcat -c
     adb shell "cd /data/local/tmp/lrt && LD_LIBRARY_PATH=. ./litert_check lib models NET --runs 10 --cache cache; echo exit \$?"
     adb logcat -d -s flatscan tflite
   then the same command again (the second run loads the serialised kernels from cache/).
5. Record per net: "gpu side ran on gpu" or the logcat reason; first and median ms (both runs); max / p99 |gpu - cpu|;
   the logcat "Replacing N out of N node(s) ... 1 partitions" and "Initialized OpenCL-based API" / "OpenGL-based API".
   Pass: ran on gpu for all three; the differences then go to the accuracy gate the integrator applies (the
   accelerator gate of docs/accel: p99 0.25 px of the page grid), which this program does not judge.
   A shell process differs from the app in its linker namespace (OpenCL lookup); the app run (app stream) is the
   final check.
