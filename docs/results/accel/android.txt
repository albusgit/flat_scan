Stream C (Android integration), steps 2-5: measured facts and how to run what needs a phone
==========================================================================================
2026-10-21, accel/c2 on accel/main 7dc7ce0. Speed mode: builds plus one emulator smoke; no phone.

What changed (app/** only)
- app/build.gradle.kts: unpackOrt extracts the AARs (they ship no prefab) into app/build/ort/<flavour>
  (headers/, jni/<ABI>/, the FS_ORT_ROOT layout of core/CMakeLists.txt); CMake gets
  -DFS_ORT_ROOT=... -DFS_ORT_QNN=ON -DFS_ORT_NNAPI=ON -DFS_ORT_XNNPACK=ON, so libflatscan links
  libonnxruntime.so and core/src/infer.cpp + nets.cpp run the nets. The Java ORT dependency is gone.
    arm64-v8a: com.microsoft.onnxruntime:onnxruntime-android-qnn:1.22.0 (QNN EP; no NNAPI EP) plus
               com.qualcomm.qti:qnn-runtime:2.33.0 libQnnHtp, libQnnHtpPrepare, libQnnSystem and the
               HTP V68/V69/V73/V75/V79 skel + stub libraries (DSP and GPU backends left out)
    other ABIs (x86_64 emulator): com.microsoft.onnxruntime:onnxruntime-android:1.22.0 (NNAPI, XNNPACK)
  -Port=plain: onnxruntime-android on arm64 too (no Qualcomm libraries). -PqnnHtp=V73,V75: fewer HTP generations.
- jni_bridge.cpp: configureNets (one Inference per group: page finder / flattening nets / shadow net),
  ortInfo, pageFinder, process (runs run_flat_nets + ShadeNet itself), benchBackends (Auto), batchPhoto
  (debug batch mode, pipeline_cli's JSON). Assets via AAssetManager; QNN cache noBackupFilesDir/qnn_cache.
- Kotlin: FlatNet.kt, PageFinder.kt, ShadeNet.kt, ShadeNetRunner and NetTiming.kt deleted; Acceleration.kt
  (Accel plans, NetEnv), Settings > Acceleration (Auto / CPU / NPU (QNN) / NNAPI (experimental); default CPU),
  Auto benchmark per (SoC, app version), batch mode (debug builds, adb intent).

Commands (Git Bash; export MSYS_NO_PATHCONV=1 for adb device paths)
- Build: JAVA_HOME=/c/Users/User/Android/jdk17 ./gradlew assembleDebug [-Pabis=arm64-v8a,x86_64] [-Port=plain]
- Inputs for the batch mode go into the app's internal storage (files adb pushes into Android/data are not
  readable by the app):  adb exec-in run-as com.albus.flatscan sh -c "mkdir -p files/batch/SET && cat > files/batch/SET/NAME.png" < LOCAL.png
- Start (debug builds; -S: fresh start, an intent to a running app only brings it to the front):
  adb shell am start -S -n com.albus.flatscan/.MainActivity --es batch SET --es accel cpu|npu|nnapi|auto
      [--es out NAME] [--ez shade true|false] [--es ext .jpg|.png] [--ez static_models true] [--es only a,b]
  Finished when /sdcard/Android/data/com.albus.flatscan/files/batch_out/OUT/done.txt exists (OUT default SET_ACCEL);
  a second start with the same OUT resumes (photos with a JSON are skipped). Pull: adb pull .../batch_out/OUT DIR.
