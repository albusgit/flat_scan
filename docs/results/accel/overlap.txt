Stream D: the flattening nets beside the CPU stages (core/src/pipeline.cpp run_photo, PipelineOptions::flat_nets)
=============================================================================================================

1. Which run_photo stages depend on the nets' grids (audit, accel/main 7dc7ce0)
---------------------------------------------------------------------------------
  page finder (logits)          before both branches: the detection and the nets' book-spread mask need it
  detect (detect_corners)       independent                                         -> CPU branch
  surface fit + quality gate    independent (its surface page may be replaced)       -> CPU branch
  the nets                      need the detection's corners only without a first-pass grid (UVDoc on
                                the whole photo failed) -> they ask for them (NetCornersFn) and wait
  flattening net check          needs the grids                                      -> after the join
  uv_defines_page / set_corners a grid can move the page corners: Uh, W / H, M change -> the orientation
                                page, the before page, the deformation grid and the paper mask follow
  stage-1 page                  remap of U, and U IS the grid whenever one is accepted (35/35 photos in
                                Gate B's s35 run are mode "uvdoc"), so it cannot be made before the
                                grids. Only the homography page is made beside the nets (it is also the
                                orientation page and the Homography-mode stage-1 page); the surface page
                                is not (it would be wasted whenever a grid is accepted)
  orientation page              the homography page of the corners: depends on the grids only through
                                uv_defines_page                                      -> CPU branch, redone if
                                                                                        the corners moved
  orientation decision          page_hw_ratio(U) (the grid's page shape) sets the resize and the turn
                                ratio: made beside the nets with the CPU branch's U, kept if the final U
                                gives the same (rows, INTER_AREA, min_ratio) on the same page, else redone
  text-row spread (2 nets), zoomed pass, warp map, compose, resample, shadows, paper mask, before page:
                                depend on the grids                                  -> after the join

So the CPU branch is: detect -> surface fit -> quality gate -> orientation page -> orientation decision;
the net branch: UVDoc on the whole photo -> UVDoc + SyntheticDoc-HR on its re-crop. ShadeNet and the
zoomed pass stay where they were (after the join, on the calling thread).

How often the speculation is redone
  orientation page: exactly when uv_defines_page fires. From Gate B's reference outputs (same decisions,
  scratchpad/accel_b/{s35_ref,du_ref}, counted with scratchpad/accel_d/count_dp.py):
    35 photos: 3 of 35   (docres__for_appearance, docres__for_deshadowing, scanner_samples__tax)
    DocUNet:  11 of 130  (2_1 6_2 8_1 10_2 15_2 17_2 28_1 51_2 57_1 60_2 62_2)
  orientation decision: the page redo plus pages whose shape test differs between the grid and the
  surface / homography (long narrow pages). Smoke only so far (see 3); the full count is in Gate D's
  gate_d_summary.txt.

2. Switches
-----------
  PipelineOptions::flat_nets (nets.h flat_nets_fn), overlap_nets (default on).
  pipeline_cli: FS_NETS=1 now runs the nets inside run_photo; FS_SEQUENTIAL=1 forces the sequential
  order (detection, then the nets on the calling thread, nothing speculative); FS_NET_DELAY_MS=n adds n ms
  to the nets without CPU load. JSON: "nets": {"overlap": {mode, orient_page_reused, orient_reused,
  nets_ms, wait_ms, join_ms, stages}}; "pipeline_ms" now includes the flattening nets.
  The app (Kotlin nets, uv_out* given in advance) is unchanged until Stream C sets flat_nets.
